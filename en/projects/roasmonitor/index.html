When a ROA expires or the RPKI publication service (Krill, for instance) fails, the ASN's prefixes start being seen as Invalid and operators running RPKI validation silently stop accepting the routes. The daemon polls each prefix at a configurable interval — against public RIPEstat or a local Routinator — and fires a Telegram alert the moment a status leaves Valid.

The problem

If a ROA expires or the RPKI server — Krill, for instance — stops, the ASN's prefixes start being seen as Invalid, and operators that validate RPKI silently drop the routes. Usually the first to notice is a customer with no internet.

Decisions

  1. 01

    Two validation sources

    It queries the public RIPEstat API or a local Routinator, chosen at install time, so the network doesn't need an outside service to watch itself.

  2. 02

    A daemon you can talk to

    It runs with a console, a command prompt and a live log, and answers /status, /check and /log on Telegram — no cron and no systemd timer.

  3. 03

    Alert on change

    It alerts when a prefix leaves Valid and when it comes back, with the prefix and ASN in the message, on the next check cycle.
