It started as an Audicom-branded LibreSpeed instance, which is still live. Version 2 is a ground-up rewrite: its own measurement engine, real UDP packet-loss testing, accounts, history on a map and a live admin dashboard — all in a single Node.js process on one VM, with no third-party services.

The problem

When a customer complains about slow internet, support asks for a test on a public site, which measures the path to another company's server rather than the provider's network. The result turns into an argument: the customer shows a number, the technician doubts it. What was missing was a measurement the provider controls end to end and that the customer can send over WhatsApp.

Decisions

  1. 01

    The server counts the upload

    Browsers overestimate uploads, so upload is counted on the server. A result that doesn't match what the server actually received is flagged as “unverified”.

  2. 02

    Real packet loss

    200 UDP packets over WebRTC with no retransmission — the same kind of traffic as calls and games. Ping and jitter come from 30 samples in a Web Worker (jitter per RFC 3550), and latency is also measured under load to catch bufferbloat.

  3. 03

    One VM, one command

    One Node.js process serves the site, runs the measurements and stores accounts and results in SQLite. On a bare Debian VM, installation takes about a minute and finishes by running the 24 automated tests.

  4. 04

    Product-grade security

    scrypt password hashing, HttpOnly SameSite __Host- session cookies, CSRF protection, login throttling, a self-hosted single-use captcha, per-page CSP with no inline scripts, an audit log of every admin action, and data export and deletion under Brazil's LGPD.

Outcome

Support now discusses a number the provider measures and verifies — and the customer gets a plain-language report (“good enough for 4K, gaming, remote work?”) with a ticket number, ready for WhatsApp.
